# flowkanvas

Canvas-first PDF generation. Users design multi-page documents of any size in the in-app editor (text, images,
rectangles, ellipses, lines, icons, QR codes, barcodes), mark dynamic parts with `{{variables}}`, image variables or
visibility conditions, then call the API with a JSON payload or multipart/form-data (text fields + image files) and
receive the rendered PDF. Custom fonts (.ttf/.otf) are uploaded once per user and embedded in PDFs.

## How it fits together

- Design JSON (`schemas/templates/design.ts`, version 2: `{ width, height, pages: [{ id, background, elements }] }`)
  is the single source of truth: the browser renders it with DOM (`components/templates/design-renderer.tsx`) and the
  server renders the same JSON to PDF with `@react-pdf/renderer` (`lib/pdf/template-document.tsx`). Units are PDF
  points, shown as px (A4 = 595 × 842). Stored v1 designs are upgraded on read by `templateDesignSchema`.
- Elements: text, image, rect, ellipse, line, icon (lucide paths in `lib/templates/icon-catalog.ts`, generated by
  `scripts/generate-icon-catalog.mjs`), qrcode (`lib/templates/qr.ts`), barcode (`lib/barcodes/` - Code 128, EAN-13).
  Every element has `condition` (visibility rule) and `group` (moves/resizes together).
- Fonts: standard 14 (Helvetica, Times, Courier) or `custom:<family>` from `template_fonts` rows
  (`lib/templates/fonts.ts`). The browser loads them via `@font-face` (`components/templates/font-faces.tsx`); the
  renderer registers them once per process with react-pdf (`lib/pdf/register-fonts.ts`). Missing families fall back to
  Helvetica with a warning header.
- Text variables: `{{name}}` inside text, QR code or barcode values. Image variables: an image element bound to a
  variable name; its static upload (if any) is the fallback when the API does not send that image. Condition
  variables only show/hide elements (`lib/templates/conditions.ts`) and are reported separately.
- react-pdf paginates anything that runs past the page bottom (text gains pages, SVG hangs), so every element is
  wrapped in a page-clipped frame in `lib/pdf/template-document.tsx`.
- `POST /api/v1/templates/[id]/generate` (API key) and `POST /api/templates/[id]/generate` (session, tester)
  share `lib/pdf/parse-generate-request.ts` → `lib/services/templates/generate-template-pdf.ts`.
- Every generate call is logged to `render_requests` (shown on `/dashboard/requests`).
- `next.config.ts` lists `@react-pdf/renderer` in `serverExternalPackages`.

## Public API

```
GET  /api/v1/templates                 -> { data: [{ id, name, width, height, pages, variables: { text, images, conditions }, updated_at }] }
GET  /api/v1/templates/:id             -> { data: { ...template, example_payload } }
POST /api/v1/templates/:id/generate    -> application/pdf
```

- Auth: `Authorization: Bearer pdf_sk_live_...`
- JSON body: `{ "payload": { "name": "Ali", "photo": "https://.../photo.jpg" } }` (flat object also accepted;
  image values may be URLs or `data:` URIs).
- multipart/form-data: text fields → text variables, file fields → image variables (PNG/JPEG, ≤10 MB).
- `variables.text` fill text boxes, QR codes and barcodes; `variables.conditions` only show/hide elements
  (send any non-empty value, or omit; `equals` rules compare the value).
- `?inline=1` returns `Content-Disposition: inline`. Missing variables are reported in
  `X-Flowkanvas-Missing-Variables`; skipped static images, missing custom fonts and invalid barcode values in
  `X-Flowkanvas-Warning`.
